# SPEC-006 — Content-Security-Policy and HSTS for the marketing site
**Gate:** GO_LIVE.md → E1 · **Surface:** static site
**Size:** M · **Depends on:** — · **Human blocker:** none

## Why

The portal ships a nonce-based CSP with `strict-dynamic`, `frame-ancestors 'none'` and
HSTS (`app/next.config.ts`, `app/src/proxy.ts`). The marketing site ships neither:

```json
// vercel.json — the complete header set today
X-Content-Type-Options · Referrer-Policy · X-Frame-Options · Permissions-Policy
```

No CSP. No HSTS. And the marketing site is the surface that **collects the PII** — name,
company, phone, email, the location and schedule of a protective detail — and posts it to
`/api/intake`. A script injected there reads the form before we ever see the lead. The
protection is inverted relative to the risk.

The site also pulls three.js from `cdn.jsdelivr.net` with an `unpkg.com` fallback, and
fonts from Google. The zero-dependency skill says: *"NO External CDNs. All assets must be
hosted locally."* Reality has drifted from the standard, and the CSP is where that drift
has to be resolved one way or the other.

## Scope

**In**
- Self-hosting three.js and the web fonts.
- A strict CSP and HSTS on the marketing site.
- The same headers in local preview, so violations surface before production.

**Out**
- The portal's CSP — already done, do not touch.
- Subresource Integrity (moot once everything is same-origin).
- Changing what any script does.

## Design

**1 · Remove the CDNs, then the policy writes itself.** Self-hosting is not a detour — it
is what lets `script-src` be `'self'` with no exceptions, and it simultaneously satisfies
the skill, removes a third-party supply-chain path into a page that handles PII, deletes
the jsDelivr→unpkg fallback complexity, and cuts two DNS/TLS handshakes off the critical
path (helping SPEC-009).

- **three.js**: vendor `three@0.160.0`'s ESM build to `js/vendor/three.module.js`, pinned,
  with its MIT licence header intact and a comment recording the version and the URL it
  came from. `js/logo-forge.js` imports the local path; the two-host fallback and the
  "every host it knows is unreachable" branch go away. Keep the WebGL-unavailable fallback
  — that failure is real and unrelated.
- **Fonts**: download the woff2 faces actually used (Cinzel, Outfit, JetBrains Mono — only
  the declared weights) into `assets/fonts/`, and replace the Google `<link>` with local
  `@font-face` in `src/styles/base.css` using `font-display: swap`. Both families are
  OFL/Apache — self-hosting is permitted; record the licence files alongside.

**2 · The policy.**

```
default-src 'self';
script-src 'self' <sha256 hashes for inline blocks>;
style-src 'self';
img-src 'self' data:;
font-src 'self';
connect-src 'self';
form-action 'self';
frame-ancestors 'none';
base-uri 'none';
object-src 'none';
upgrade-insecure-requests
```

Plus `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`, matching
the portal. Change `X-Frame-Options` to `DENY` to agree with `frame-ancestors 'none'` —
`SAMEORIGIN` alongside it is a contradiction.

**3 · Inline blocks get hashes, not `unsafe-inline`.** The pages carry
`<script type="application/json">` (the `#fps-config` island) and
`<script type="application/ld+json">` (schema.org). Neither executes, but browsers differ
on whether they are blocked or merely reported, and Google's crawler must keep reading the
JSON-LD. Hashing is the only answer that is correct everywhere, and it costs nothing at
build time.

**4 · Generate `vercel.json`, and check it like every other artefact.** Hashes change
whenever the data island changes, so a hand-maintained header is guaranteed to rot. Make
`build.mjs` compute the sha256 of each inline block and emit `vercel.json`, then register
it in `artefacts()` so `node build.mjs --check` catches drift exactly as it does for HTML
and CSS. This is the repository's existing philosophy — generated output is committed and
verified — applied to the one config file that must track the markup.

Determinism: hashing is pure over the generated bytes, so `--check` stays stable across
machines and dates. No clock, no network.

**5 · Preview parity.** `serve.py` sends the same headers. A CSP that only exists in
production is a CSP you debug in production.

**6 · Report before enforce.** Ship one deploy with `Content-Security-Policy-Report-Only`
(reporting to the SPEC-003 endpoint if it has landed, otherwise the browser console),
confirm zero violations on `/`, `/careers`, `/invoice` and the three legal pages in
Chrome, Firefox and Safari, then flip to enforcing in a follow-up commit on the same PR.

## Acceptance

1. No request leaves the origin on any page — verified with the network panel filtered to
   third-party — except the form POST to our own `/api/intake`.
2. `js/logo-forge.js` imports three.js from a same-origin path; no CDN host remains in any
   source or generated file.
3. Fonts load from `assets/fonts/` with licences committed; no `fonts.googleapis.com` or
   `fonts.gstatic.com` reference survives.
4. The CSP is exactly as in design 2, contains no `unsafe-inline` or `unsafe-eval`, and
   every inline block is covered by a hash.
5. `vercel.json` is generated by `build.mjs` and covered by `--check`; editing it by hand
   and running `--check` fails.
6. Zero CSP violations on all six pages in Chrome, Firefox and Safari.
7. Schema.org JSON-LD still parses — confirmed with Google's Rich Results Test.
8. `serve.py` sends the same headers as production.
9. HSTS present; `X-Frame-Options: DENY`.
10. The assembly intro, the fallback plate and reduced-motion behaviour are unchanged.

## Test plan

- `tests/csp.test.mjs`: parse the generated `vercel.json`; assert the directive set, the
  absence of `unsafe-*`, and that every `<script>` block in every generated page has a
  matching hash in `script-src`.
- Drift test: mutate a data file, rebuild, assert the hash changed; hand-edit `vercel.json`,
  assert `--check` exits 1.
- Manual, recorded in the PR: the three-browser violation sweep and the Rich Results Test.

## Files

`build.mjs` (hashing + `vercel.json` artefact) · `vercel.json` (becomes generated) ·

## Open decisions

- **Self-host, or allowlist the CDNs?** *Recommended: self-host.* Allowlisting is two lines
  and keeps a third-party origin able to run script on the page that collects PII, while
  leaving the repository in violation of its own skill. Self-hosting costs ~600 KB of
  committed vendor assets and settles it permanently.
- **Generate `vercel.json` or hand-maintain the hashes?** *Recommended: generate.* Hand-
  maintained hashes break the moment anyone edits `src/data/`, and they break silently —
  the page keeps working while the policy stops matching.
- **`frame-ancestors 'none'` and `/invoice`:** confirm nothing embeds the invoice page in an
  iframe for printing before enforcing. If something does, say so rather than loosening the
  directive.
